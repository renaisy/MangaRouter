## 1. 前置准备

| 项 | 要求 | 说明 |
|----|------|------|
| 中央节点主机 | 8G+ 内存、50G+ 硬盘、可 24h 开机 | 团队内一台常开电脑或迷你主机 |
| 操作系统 | Windows 10/11、macOS、Linux 均可 | 推荐 Linux/Windows + WSL2 |
| Docker | 已安装 Docker + Docker Compose v2 | 见下文安装指引 |
| 火山引擎账号 | 已实名认证、已开通 Seedance 模型 | console.volcengine.com |
| 第三方聚合渠道账号 | 至少 1 家（可选） | 用于省钱兜底 |

### 安装 Docker
- **Windows**：安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)，启用 WSL2 后端
- **macOS**：安装 Docker Desktop 或 [OrbStack](https://orbstack.dev/)（更省资源）
- **Linux**：`curl -fsSL https://get.docker.com | sh`

验证：`docker --version` 与 `docker compose version` 都能输出即可。

## 2. 选定并配置中央节点

1. 选定一台 24h 开机的电脑作为**中央节点**
2. 记下它的内网 IP（如 `192.168.1.50`），后面所有人访问都用这个 IP
   - Windows：`ipconfig` 看 IPv4 地址
   - Linux/Mac：`ip addr` 或 `ifconfig`
3. 把本项目目录 `seedance-hub/` 放到这台电脑上（任意位置均可）

### 防火墙放行端口
中央节点要放行以下端口（仅限内网 / ZeroTier 虚拟网，**不要**对公网开放）：

| 端口 | 服务 |
|------|------|
| 13000 | New-API |
| 18080 | NocoDB |
| 19000 / 19001 | MinIO API / 控制台 |
| 18008 | Seedance 适配器（可选） |
| 18501 | 分镜提交工具（可选） |

- **Windows**：控制面板 → 防火墙 → 高级设置 → 入站规则 → 新建 → 端口 → 上述 TCP 端口 → 允许
- **Linux**：`sudo ufw allow 13000,18080,19000,19001,18008,18501/tcp`

## 3. 一键启动三大服务

在中央节点的 `seedance-hub/` 目录下：

```bash
# 1. 复制环境变量模板
cp .env.example .env

# 2. 编辑 .env，把所有 <请改成强随机密码> 换成真实密码
#    Windows 可用记事本打开编辑
notepad .env      # Windows
nano .env         # Linux/Mac

# 3. 生成强随机密码（可选，在命令行执行）
openssl rand -hex 24

# 4. 启动！
docker compose up -d

# 5. 查看启动状态
docker compose ps
```

全部 `healthy` 后，用浏览器在本机访问验证：

| 服务 | 地址 | 初始账号 |
|------|------|---------|
| New-API | http://localhost:13000 | root / 123456（**立即改密**） |
| NocoDB | http://localhost:18080 | 首次访问引导注册管理员 |
| MinIO 控制台 | http://localhost:19001 | .env 里的 ROOT_USER / ROOT_PASSWORD |

> ⚠️ **首次登录 New-API 后立即修改 root 密码**（右上角头像 → 个人设置）。

## 4. 配置 ZeroTier 分布式组网

让分散的团队成员像在同一个局域网一样访问中央节点。

### 4.1 创建网络（中央节点执行一次）
1. 注册 https://my.zerotier.com 免费账号
2. `Networks` → `Create A Network`，得到一个 **16 位 Network ID**
3. 点进这个网络，把 `Access Control` 设为 **Private**（私有，需审批）
4. 记下 Network ID，告诉所有成员

### 4.2 中央节点加入网络
- **Windows/Mac**：下载安装 [ZeroTier 客户端](https://www.zerotier.com/download/)，托盘图标 → Join Network → 输入 Network ID
- **Linux**：`curl -s https://install.zerotier.com | sudo bash && sudo zerotier-cli join <网络ID>`
- 回到 my.zerotier.com 网络页面，在 `Members` 列表里**勾选 auth** 给这台机器
- 记下它被分配的虚拟 IP（形如 `10.147.17.x`）—— **这就是团队访问中央节点要用的 IP**

### 4.3 团队成员加入（每人重复一次）
1. 各自下载安装 ZeroTier 客户端
2. Join Network → 输入同一个 Network ID
3. 等管理员在后台勾选 auth 授权
4. 用浏览器访问 `http://<中央节点虚拟IP>:13000` 即可打开 New-API

> 💡 个人版 ZeroTier 免费支持 25 个节点，10 人团队完全够用。
> 若 ZeroTier 在某些网络下打洞失败延迟高，可改用 FRP（需租 VPS，见附录）。

## 5. New-API 渠道与智能路由配置

登录 New-API（http://中央节点IP:13000），用 **root** 账号操作。**全程图形化，零代码。**

### 5.1 添加渠道（「渠道」菜单 → 添加渠道）

为每个 Seedance 来源建一个渠道：

| 渠道名 | 类型 | Base URL / 密钥 | 模型 | 分组 |
|--------|------|-----------------|------|------|
| 火山官方-mini | VolcEngine / OpenAI 兼容 | 方舟 API Key | doubao-seedance-2-0-mini | **draft** |
| 火山官方-fast | 同上 | 方舟 API Key | doubao-seedance-2-0-fast | **standard** |
| 火山官方-2.0 | 同上 | 方舟 API Key | doubao-seedance-2-0 | **final** |
| 第三方聚合A | OpenAI 兼容 | 聚合商提供的 key + URL | 对应模型名 | draft/standard |

- **类型**：New-API 已有 Volcengine 适配就选它；没有就选 `OpenAI` 并填方舟兼容地址
- **分组**：就是智能路由的钥匙，填 `draft` / `standard` / `final` 之一
- **权重**：同组多个渠道时，官方填高权重（如 100），聚合渠道填低权重兜底（如 30）
- **优先级**：数字越小越优先

### 5.2 测试渠道
每个渠道建好后，点列表里的「测试」按钮，确认能通。

### 5.3 为每个成员建令牌（「令牌」菜单 → 添加令牌）
- 给 10 位成员各建一个令牌，命名如 `张三-提交`、`李四-提交`
- 可设额度上限（每月预算控制）
- 把令牌字符串发给对应成员（或填到提交工具）

### 5.4 （关键）验证 Seedance 异步调用是否走通
在「日志」或用 curl 测一次：

```bash
curl -X POST http://中央节点IP:13000/v1/videos \
  -H "Authorization: Bearer <你的令牌>" \
  -H "Content-Type: application/json" \
  -d '{"model":"doubao-seedance-2-0-fast","prompt":"测试：一只猫在月光下"}'
```

- ✅ **返回 task_id 且能查到结果** → New-API 已原生支持，**跳过第 7 节**
- ❌ **报错或不支持** → 需要部署第 7 节的适配器

## 6. NocoDB 协作平台建表

1. 浏览器打开 http://中央节点IP:18080，注册管理员账号
2. 新建一个 Base，命名为「漫剧协作」
3. 记下 Base ID（地址栏 `#/nc/p_xxxxx` 里 `p_` 后那串）
4. 在 Base 设置 → API Tokens 生成一个 token
5. 在中央节点命令行跑初始化脚本：

```bash
cd seedance-hub/nocodb-init
pip install httpx
python init_schema.py
# 按提示输入 NocoDB 地址、Token、Base ID
```

6. 完成后会创建 3 张表：**Projects / Storyboards / Costs**
7. 记下 **Storyboards 表的 tableId**（脚本会打印出来），后面填到提交工具

> 建好表后建议在 NocoDB 网页里把列的显示名改成中文（在列头右键 → Edit），非技术成员更友好。

## 7. 部署 Seedance 适配器（按需）

> 仅当第 5.4 步发现 New-API 不能直接调通 Seedance 时才需要。

```bash
cd seedance-hub/seedance-adapter

# 1. 在 .env（项目根目录）里确认已填：
#    VOLC_API_KEY=<火山方舟 API Key>
#    VOLC_BASE_URL=https://ark.cn-beijing.volces.com/api/v3

# 2. 构建并运行
docker build -t seedance-adapter .
docker run -d --name seedance-adapter \
  --network host \
  --env-file ../.env \
  -p 18008:18008 \
  seedance-adapter

# 3. 验证
curl http://localhost:18008/health
# 应返回 {"status":"ok","api_key_configured":true}
```

然后在 New-API 的「火山官方」渠道里，把 **Base URL 改为** `http://<中央节点内网IP>:18008`，
这样 New-API 会把 Seedance 请求转发给适配器，适配器再调方舟。

## 8. 部署分镜提交小工具

```bash
cd seedance-hub/submit-tool
docker build -t seedance-submit .
docker run -d --name seedance-submit \
  --network host \
  --env-file ../.env \
  -e ADAPTER_URL=http://localhost:18008 \
  -p 18501:18501 \
  seedance-submit
```

浏览器打开 http://中央节点IP:18501 即可使用。

> 提交工具默认连中央节点本机；在 `.env` 里把
> `SUBMIT_NEWAPI_BASE_URL` / `NOCODB_BASE_URL` / `SUBMIT_MINIO_ENDPOINT`
> 改成中央节点的**内网/ZeroTier IP** 即可。

## 8.5 （v0.2 新增）部署 ComfyUI 专业模式（按需）

> 仅当团队需要首尾帧、多参考图、角色一致性等高级能力时启用。
> ComfyUI 装在**专家自己的电脑**上（不是中央节点），因为它只是创作界面，调云端 API，不需要 GPU。
> 详见 [`ComfyUI接入指南.md`](ComfyUI接入指南.md)。

### 专家电脑上安装
1. 下载 https://www.comfy.org/download 桌面版并安装
2. 启动时带参数（或修改快捷方式）：
   ```
   python main.py --enable-cors-header --listen 0.0.0.0 --port 8188
   ```
   - `--enable-cors-header` **必须**，否则 Streamlit 调用桥跨域被拦
   - `--listen 0.0.0.0` 让其它成员经 ZeroTier 也能访问专家的 ComfyUI
3. Manager → 安装 ByteDance Seedance 官方节点包，重启
4. 节点里把 API Base URL 填适配器地址 `http://<中央节点IP>:18008`，API Key 填 New-API 令牌

### 配置 Streamlit 调用桥
在 `.env` 里加：
```
COMFYUI_BASE_URL=http://<专家电脑的ZeroTier IP>:8188
```
重启提交工具即可。成员在「ComfyUI 专业模式」里选模板触发。

### 放置工作流模板
专家搭好工作流后，导出 API 格式 JSON，改占位符，放到中央节点
`submit-tool/templates/` 目录，成员立即能在 Streamlit 看到。

仓库已附 3 个模板骨架：
- `seedance_first_last_frame.json`（首尾帧）
- `seedance_multi_reference.json`（多参考图）
- `seedance_real_human.json`（角色一致性）

> 专家需用 ComfyUI 实际导出的节点结构替换骨架里的占位节点。

## 9.5 （v0.3 新增）成本看板与计费同步

> 这套让团队"花的每一分钱都看得见"。计费同步自动采集，看板自动可视化。

### 前置：在 .env 里填好同步配置
```
COST_NEWAPI_TOKEN=<New-API 管理员令牌>
COST_NOCODB_TOKEN=<NocoDB API Token>
COST_NOCODB_TABLE_ID=<Costs 表的 tableId，建表脚本会打印>
# 可选：改调度频率（默认每天 01:05）
# COST_SYNC_CRON="5 */6 * * *"   每6小时一次
```

### 启动（已在 docker-compose 里，一键起）
```bash
docker compose up -d cost-sync cost-dashboard
```

### 验证
1. 手动跑一次同步（不等 cron）：
   ```bash
   docker compose run --rm cost-sync python sync.py --days 7 --dry-run
   ```
   看到"共 N 条消费记录，合计 ¥XXX"即正常。
2. 去掉 `--dry-run` 真正写入：
   ```bash
   docker compose run --rm cost-sync python sync.py --days 7
   ```
3. 打开看板：`http://<中央节点IP>:18502`
   - 顶部 4 个 KPI（总花费/调用次数/Tokens/日均）
   - 趋势线 + 成员/渠道/模型排名 + 三档分组占比
4. 之后 cron 每天 01:05 自动同步昨天数据，无需干预

### 看板解读要点
- **final 占比过高** → 有人在用最贵的成片档试错，提醒改用 draft 档迭代
- **某成员花费突增** → 点趋势线查看，确认是项目需要还是操作问题
- **某渠道单价异常** → 对照 New-API 日志，可能要调权重（见 New-API渠道配置.md）

## 10. 日常运维

### 备份
- **数据库**：定期备份 `data/newapi/mysql` 与 `data/nocodb/mysql` 两个目录
- **MinIO 数据**：备份 `data/minio`
- 最简单：整目录打包 `tar -czf backup-$(date +%F).tar.gz data/`

### 更新
```bash
docker compose pull      # 拉最新镜像
docker compose up -d     # 重建容器（数据保留）
```

### 查看日志
```bash
docker compose logs -f new-api      # 看网关日志
docker compose logs -f minio        # 看存储日志
docker logs -f seedance-adapter     # 看适配器日志
```

### 调价优化（每周做一次）
1. New-API「日志」页按渠道统计上周花费与成功率
2. 成功率低/单价高的渠道降权重
3. 把表现好的提示词沉淀到 NocoDB，复用降低调用次数

## 附录 A：用 FRP 替代 ZeroTier（追求更稳定）

若 ZeroTier 在团队网络下延迟高，可租一台国内 VPS（约 ¥30/月）跑 frps：

1. VPS 上：下载 [frp](https://github.com/fatedier/frp)，写 `frps.toml`：
   ```toml
   bindPort = 7000
   auth.token = "强随机字符串"
   ```
   `./frps -c frps.toml`
2. 中央节点上写 `frpc.toml`：
   ```toml
   serverAddr = "VPS公网IP"
   serverPort = 7000
   auth.token = "同上"
   [[proxies]]
   name = "newapi"
   type = "tcp"
   localIP = "127.0.0.1"
   localPort = 13000
   remotePort = 13000
   # 对 18080/19000/19001/18008/18501 各加一个 proxy
   ```
   `./frpc -c frpc.toml`
3. 团队成员访问 `http://<VPS公网IP>:13000` 即可

> 注意：暴露到公网务必配合 HTTPS 与强密码，详见 New-API 安全文档。
