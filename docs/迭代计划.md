# 迭代计划与优化方向

> 本文档规划 MangaRouter 的演进路线，按"近期（1-2 周）/中期（1-2 月）/远期（季度）"三档组织。
> 每项标注**价值**、**工作量**、**依赖**，便于排期决策。
>
> 原则：先解决"用得痛"的（近期），再做"用得爽"的（中期），最后追"用得强"的（远期）。

---

## 一、当前能力盘点（v0.3.3）

| 能力域 | 现状 | 成熟度 |
|--------|------|--------|
| 智能路由 | 三档分组 + 权重 + 多渠道兜底 | ✅ 生产可用 |
| 视频生成 | 文生/首帧/首尾帧/多参考图/角色一致性 | ✅ 生产可用 |
| 团队协作 | NocoDB 项目/分镜/审核 + MinIO 归档 | ✅ 生产可用 |
| 计费管理 | 自动同步(分页上限/异常包装) + 看板可视化 | ✅ 生产可用 |
| 分布式协同 | ZeroTier 组网 | ✅ 生产可用 |
| 复杂工作流 | ComfyUI 专家模式（模板需专家填充） | ⚠️ 框架就绪，内容待补 |
| 工程质量 | 42 个单测、非root、端口绑回环、日志轮退 | ✅ v0.3.3 加固完成 |

**v0.3.x 已完成的加固**：NocoDB PATCH 契约修正、表结构 dt 类型映射、建表幂等、
计费同步分页上限/异常包装/浮点修正、compose 网络/日志/资源限制、适配器轮询退避。

**当前主要短板**（按影响排序）：
1. **submit-tool 提交阻塞**：900s 同步等待撑爆 Streamlit，多用户互相阻塞（架构级，最痛）
2. **成片分享靠控制台**：看/下载成片要登 MinIO，无预签名链接
3. **审核靠人工刷表**：成片生成后审核人不知道
4. **ComfyUI 模板未落地**：3 个骨架需专家填充真实结构
5. 多剧隔离弱、夜间算力未利用、生成结果无法去重复用

## 二、近期迭代（v0.4 ~ v0.5，1-2 周）

> 目标：攻克 submit-tool 异步化（最痛的架构债），并补齐成片分享与审核通知。

### P1-1：submit-tool 异步化（核心架构改造，最优先）⭐⭐⭐

这是当前**最大的用户体验瓶颈和架构债**，详细展开如下。

#### 痛点（为什么必须改）
- 现状：`submit_via_newapi` 用 `httpx.post(..., timeout=900)` 同步阻塞 Streamlit 主线程最长 15 分钟
- 后果①：**多用户互相阻塞**——Streamlit 单线程，A 提交后 B 操作全部卡死直到 A 出结果
- 后果②：**刷新即丢任务**——WebSocket 心跳超时（默认 60-120s）或用户刷新页面，正在等的结果丢失，且无任何持久化，任务变成"薛定谔状态"（不知道还在跑还是没了）
- 后果③：**长任务无进度**——只有个转圈 spinner，用户不知道还要等多久

#### 方案（提交-轮询-回调三段式）
```
用户点提交
   ↓
POST /v1/videos（异步，立即返回 task_id）   ← 不再 POST /v1/videos/sync
   ↓
task_id 写入 NocoDB Storyboards.Status=running + TaskId 字段
   ↓
前端轮询 GET /v1/videos/{task_id}（每 5-10s，页面可刷新/切换/关掉都不影响）
   ↓
succeeded → 下载归档 MinIO + 回填 NocoDB + 页面通知
failed    → 回填错误 + 页面提示
```

#### 具体改动点
1. **submit-tool/app.py**：
   - `submit_via_newapi` 改为调 `/v1/videos`（异步）拿 task_id，立即返回
   - 新增"我的任务"侧栏：从 NocoDB 读 `Status=running` 的行，前端 JS 轮询状态
   - Streamlit 用 `st.fragment` + `st.rerun` 做轮询，或用 `streamlit-autorefresh` 组件
2. **Storyboards 表**：加 `TaskId` 字段（存方舟任务 ID，供轮询）、`ErrorMsg` 字段（失败原因）
3. **归档逻辑**（补 P0-3 遗留）：任务 succeeded 后，下载 video_url 存 MinIO outputs 桶，回填 `VideoUrl`/`MinioPath`
4. **并发安全**：轮询由前端驱动（每个用户轮询自己的 task_id），不再占主线程

#### 风险与对策
- **风险**：Streamlit 的轮询机制不如原生 JS 优雅，`st.rerun` 频繁会闪屏
  → 对策：用 `streamlit-autorefresh` 组件做定时刷新，或把轮询放进 `@st.fragment` 局部刷新
- **风险**：用户关掉浏览器后任务状态不更新
  → 对策：加一个后台 worker（轻量 loop，类似 cost-sync）定期扫 NocoDB 里 running 的任务补状态
- **工作量**：~3-4 天（含测试）

### P1-2：成片预签名 URL 分享

- **痛点**：看/下载成片要登 MinIO 控制台
- **方案**：归档时用 `minio.presigned_get_object` 生成 7 天时效链接，存入 NocoDB `ShareUrl` 字段
- **价值**：⭐⭐⭐ 直接改善每人每天体验；也是 P1-3 审核通知的前置
- **工作量**：~1 天（MinIO SDK 原生支持）
- **依赖**：P1-1 的归档逻辑（链接在归档时一起生成）

### P1-3：审核通知自动化（飞书/钉钉 webhook）

- **痛点**：成片生成后审核人不知道，要主动刷表
- **方案**：归档成功后，按 Storyboards 的审核人字段，调飞书/钉钉 webhook 推消息（含预签名链接 + 镜头号 + 提示词摘要）
- **价值**：⭐⭐⭐ 缩短"生成→审核"周转
- **工作量**：~1-2 天
- **依赖**：P1-2（链接生成）

### P1-4：ComfyUI 模板实战填充

- **痛点**：3 个模板还是骨架，需专家用真实导出结构替换
- **方案**：专家按 ComfyUI 接入指南培训后，产出真实可用的首尾帧/多参考图/角色一致性模板，提交 PR
- **价值**：⭐⭐⭐ 让"高级能力"真正落地
- **工作量**：~3-5 天（含专家学习曲线，可与 P1-1 并行）
- **依赖**：团队有人完成 ComfyUI 培训

### P1-5：cost-dashboard 健壮性收尾（P2 剩余）

- **痛点**：看板几处边界处理不完整（P2 审查遗留）
- **方案**：
  - `safe_filter` 兜底改为返回空 df + warning（Date 列缺失时不再掩盖问题）
  - `fillna(0)` 改为保留 NaN 或单独计数缺失（避免拉低均值）
  - `table_id` 加格式校验（`^m[A-Za-z0-9]+$`）
  - 用 `@st.fragment` 隔离交互区块，减少整页重渲染
- **价值**：⭐⭐ 看板准确性与体验
- **工作量**：~1 天
- **依赖**：无

## 三、中期迭代（v0.6 ~ v0.8，1-2 月）

> 目标：从"能用"到"好用"，覆盖规模化生产场景。

### P1-1：多项目/多剧隔离

- **痛点**：现在所有剧的成本/素材混在一起，不同剧组互相可见
- **方案**：
  - NocoDB 表加 `ProjectKey` 字段，按项目过滤视图
  - MinIO 桶按项目分子目录 + 按项目分配访问策略
  - New-API 按项目建不同令牌，额度独立
- **价值**：⭐⭐⭐ 多剧组并行必备
- **工作量**：~1 周
- **依赖**：无

### P1-2：离线批量调度（夜间低价/队列）

- **痛点**：草稿迭代占用白天时间，且 Seedance 可能有夜间低谷折扣
- **方案**：提交工具支持"挂起任务"，由调度器在指定时段（如 23:00-07:00）批量跑草稿档
- **价值**：⭐⭐ 省钱 + 省人时
- **工作量**：~1 周
- **依赖**：无

### P1-3：生成结果智能复用（去重缓存）

- **痛点**：相同提示词+seed+图片的请求会重复计费
- **方案**：在适配器/网关层加内容哈希缓存，命中则直接返回历史结果（不调上游）
- **价值**：⭐⭐ 长期省钱，尤其调试期
- **工作量**：~1 周（含缓存淘汰策略）
- **依赖**：无

### P1-4：自动成本预警

- **痛点**：现在成本是"事后看"，超预算才发现
- **方案**：
  - cost-sync 检测到某成员/项目当日花费超阈值 → 推预警消息
  - New-API 令牌额度硬限制 + 软预警双保险
- **价值**：⭐⭐⭐ 防失控
- **工作量**：~3 天
- **依赖**：P0-2（通知通道）

### P1-5：分镜表的版本与对比

- **痛点**：一个镜头反复生成多版，难以对比择优
- **方案**：Storyboards 表支持一个镜头挂多个成片（版本号），看板里并排预览对比
- **价值**：⭐⭐ 提升选片效率
- **工作量**：~1 周
- **依赖**：P0-1（预签名 URL）

## 四、远期演进（v1.0+，季度级）

> 目标：平台化与生态扩展，从"团队工具"升级为"生产能力"。

### P2-1：多模型供应商抽象（不止 Seedance）

- **方向**：把适配器抽象成统一视频生成协议，支持接入可灵、即梦、Sora、WAN、MiniMax 等
- **价值**：⭐⭐⭐ 避免 Seedance 单点依赖，跨模型比价比质
- **工作量**：2-3 周

### P2-2：成片后处理流水线

- **方向**：生成 → 自动配音(TTS) → 字幕 → 拼接 → 调色 → 导出
- **价值**：⭐⭐ 从"生成片段"到"交付成片"
- **工作量**：3-4 周（可逐步引入 FFmpeg/语音模型）

### P2-3：Web 前端独立化（脱离 Streamlit）

- **方向**：当前 Streamlit 适合内部，但定制性和体验有天花板。规模化后用 Vue/React 重做前端
- **价值**：⭐⭐ 体验跃升，但要团队有前端能力
- **工作量**：4-6 周
- **前提**：确认 Streamlit 真的成为瓶颈再做，避免过度工程

### P2-4：角色一致性资产库

- **方向**：把 ComfyUI 的 Group ID 资产管理独立成模块，按剧/角色组织，跨镜头跨集复用
- **价值**：⭐⭐⭐ 漫剧核心痛点（角色一致性）
- **工作量**：2-3 周
- **依赖**：P0-4（ComfyUI 模板落地）

### P2-5：私有化部署与安全加固

- **方向**：支持纯内网/专有云部署、SSO 单点登录、审计日志、数据加密
- **价值**：⭐⭐ 面向企业/商单场景
- **工作量**：2-3 周

## 六、开源协作规划

本项目已开源至 https://github.com/renaisy/MangaRouter ，欢迎社区参与：

- **Issue 模板**：bug 报告 / 功能建议 / 渠道适配请求
- **PR 欢迎**：尤其是新的第三方渠道适配、ComfyUI 工作流模板、提示词模板贡献
- **路线共建**：如果你有急迫需求不在本计划里，欢迎开 Issue 讨论

### 贡献优先级（社区友好）
1. 更多 Seedance 渠道的接入实测反馈（哪些聚合商支持首尾帧）
2. ComfyUI 工作流模板的真实化（最受惠的 Contribution）
3. 多模型的适配器扩展（可灵/即梦等）
4. 文档勘误与本地化

## 七、版本节奏

- **patch**（0.3.x）：bug 修复、文档、小优化
- **minor**（0.4, 0.5...）：新功能，向后兼容
- **major**（1.0）：架构级变化或能力质变

预计节奏：每 1-2 周一个 minor 版本，重大里程碑打 major。
