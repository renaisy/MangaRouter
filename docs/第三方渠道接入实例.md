# 第三方聚合渠道接入实例

> 本文档讲清楚：除火山官方外，怎么把第三方聚合平台（OpenAI 兼容协议）接入我们的体系，
> 实现"同模型多渠道比价、便宜渠道兜底"的省钱目标。
>
> 覆盖两个层面：①在 New-API 网关配置（统一计费/路由）；②在 ComfyUI 直连（专家本地调试）。

---

## 一、为什么要接第三方聚合渠道

火山方舟是官方源，价格透明但无折扣。第三方聚合平台往往：
- 以**略低于官方**的价格（普遍便宜 10-15%）转售同样的 Seedance 能力
- 提供**统一 OpenAI 兼容协议**，接入简单
- 可作为**兜底**：官方限流/故障时自动切换

在我们的智能路由里，第三方渠道通常放在**同组的低权重位置**——非紧急任务走它省钱，关键镜头仍走官方保质量。

---

## 二、常见的 Seedance 聚合渠道（2026-08 调研）

| 平台 | 协议 | Seedance 支持 | 特点 | 备注 |
|------|------|--------------|------|------|
| [API 易 (apiyi.com)](https://docs.apiyi.com/api-capabilities/seedance2/video-generation) | OpenAI 兼容 | Seedance 2.0 全模式 | 文档全，价格表清晰，有 FLF2V/R2V 参数说明 | 起步推荐 |
| [LoopRouter](https://docs.looprouter.com/api-capabilities/seedance2/video-generation) | OpenAI 兼容 | Seedance 2.0 | 模式速查表清晰，适合对照参数 | 备选 |
| [实在 Agent (ai-indeed.com)](https://www.ai-indeed.com/encyclopedia/20205.html) | 自有 | Seedance 系列 | 套餐制，部分套餐较官方便宜 ~12% | 适合走量 |

> ⚠️ **风险提示**：第三方聚合渠道存在跑路/调价/质量波动风险。**绝不要把所有流量都放一个第三方**，始终保留官方渠道为主。建议同组内官方权重 100、第三方权重 30-50 兜底。

> 选型时务必确认对方支持你要用的模式（首尾帧/多参考图），有些聚合商只支持文生视频和首帧。

## 三、接入方式一：在 New-API 网关配置（推荐，统一计费）

这是主路径——所有第三方渠道都先配进 New-API，让 New-API 的智能路由统一调度。**普通成员和 ComfyUI 都走 New-API**，不用每处单独配。

### 第 1 步：在聚合平台开账号拿 Key
以 API 易为例：
1. 注册 https://apiyi.com 账号
2. 充值（先小额试水，如 ¥50）
3. 在「API Keys」页创建一个 Key，记下 `sk-xxxx`
4. 记下 Base URL，通常形如 `https://api.apiyi.com/v1`

### 第 2 步：在 New-API 后台添加渠道
「渠道」→「添加渠道」：

| 字段 | 填什么 |
|------|--------|
| 类型 | **OpenAI**（聚合商都是 OpenAI 兼容协议） |
| 名称 | `API易-mini`（自定义） |
| Base URL | `https://api.apiyi.com/v1`（聚合商给的） |
| 密钥 | `sk-xxxx`（聚合商的 Key） |
| 模型 | 填聚合商支持的模型名，如 `doubao-seedance-2-0-mini`（按对方文档） |
| 分组 | 放进对应组：省钱兜底就放 `draft` 或 `standard` |
| 权重 | **低权重**，如 30（官方渠道设 100） |
| 优先级 | 数字大些（让官方优先） |

### 第 3 步：测试渠道
点列表里的「测试」按钮。
- 成功 → 该渠道已可用，New-API 会在官方渠道失败/限流时自动切到它
- 失败 → 检查 Base URL、Key、模型名是否与聚合商文档一致

### 第 4 步：观察并调权重
用几天后，在「日志」页看这个渠道的：
- **成功率**：<95% 就降权重或禁用
- **实际单价**：和官方对比，确认确实便宜
- **平均耗时**：太慢就降权

> 关键原则：**第三方是"锦上添花"不是"唯一依赖"**。任何渠道出问题，官方渠道必须能顶上。

## 四、接入方式二：在 ComfyUI 直连（专家本地调试用）

专家搭工作流调试时，可能想绕过 New-API 直连某个聚合渠道快速试错。
（生产环境仍建议走 New-API，这里只是调试场景。）

### 方法 A：用第三方火山引擎插件（如 ComfyUI-Jimeng-API）
1. ComfyUI Manager → 安装 `ComfyUI-Jimeng-API`（GitHub: fkxianzhou/ComfyUI-Jimeng-API）
2. 该插件支持自定义 Base URL 和 API Key
3. 在节点里填：
   - **Base URL** = 聚合商地址，如 `https://api.apiyi.com/v1`
   - **API Key** = 聚合商的 `sk-xxxx`
4. 该插件已支持 Seedance 2.0 的文生/首帧/首尾帧

### 方法 B：用官方 ByteDance 节点改配置
官方 Seedance 节点同样允许改 endpoint：
1. 双击 Seedance 节点，找 `api_base` 或 `base_url` 参数
2. 改成聚合商地址
3. API Key 填聚合商的

> 调试完记得**改回 New-API 地址**（`http://<中央节点IP>:18008`），否则该专家的调用不进统一计费。

## 五、首尾帧/多参考图在第三方渠道的注意点

不是所有聚合渠道都完整支持 Seedance 的四种模式。**接入前务必验证**：

| 验证项 | 方法 |
|--------|------|
| 文生视频 | 最基础，一般都支持 |
| 首帧图生视频 | 传 1 张图 + role=first_frame，看是否报错 |
| **首尾帧** | 传 2 张图（first_frame + last_frame），**很多廉价渠道不支持** |
| **多参考图** | 传 N 张 reference_image，部分渠道限制数量 |

验证命令（用 curl 直连聚合商，先小成本测）：
```bash
# 测首尾帧
curl -X POST https://api.apiyi.com/v1/videos \
  -H "Authorization: Bearer sk-xxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seedance-2-0",
    "content": [
      {"type": "text", "text": "镜头从白天过渡到夜晚"},
      {"type": "image_url", "image_url": {"url": "https://你的首帧.jpg"}, "role": "first_frame"},
      {"type": "image_url", "image_url": {"url": "https://你的尾帧.jpg"}, "role": "last_frame"}
    ]
  }'
```
返回 task_id 即支持；报 role 相关错误则该渠道不支持首尾帧——**别把这个渠道放进 final 组**。

## 六、成本对比与切换决策

每周在 NocoDB 的 Costs 表（由 `cost-sync/sync.py` 自动填充）里对比：

| 渠道 | 上周花费 | 调用次数 | 平均单价 | 成功率 |
|------|---------|---------|---------|--------|
| 火山官方-fast | ¥320 | 450 | ¥0.71/次 | 99% |
| API易-fast | ¥45 | 80 | ¥0.56/次 | 97% |

决策：
- 第三方成功率 ≥95% 且单价低 10%+ → 提高其权重（多走量省钱）
- 第三方成功率 <90% → 降权或弃用（省钱不抵返工成本）
- 关键镜头（final 组）→ **永远只用官方**，不接第三方

---

## 七、安全与合规

1. **Key 保管**：聚合商 Key 只存在 New-API 后台，不要明文发给成员
2. **充值限额**：第三方平台充值先小额，确认稳定再加量，避免跑路损失
3. **数据合规**：第三方渠道会经手你的图片/视频数据，敏感项目（含真人肖像）**优先用官方**，避免数据泄露风险
4. **备案**：建议在 NocoDB Costs 表的 Channel 字段记录每次花费来源，便于追溯
